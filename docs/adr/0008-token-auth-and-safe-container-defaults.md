# ADR-0008: トークン認証と、安全な既定のコンテナ構成

## Status
Accepted (2026-10-28). [ADR-0001](0001-celery-and-redis.md) の構成の、公開時の既定を変える。

## Context
認証がなく、CORS の既定が `*`、Redis がホストの 6379 にパスワードなしで公開され、画面のコンテナは開発サーバーで動いていた。
ローカルでの開発・デモは、これまでどおり、設定なしで動かしたい。

## Decision
- `QUEUEWATCH_AUTH_MODE`: `local`(既定、認証なし)と `token`(`Authorization: Bearer`)。ロールは viewer(閲覧)・editor(投入・操作)・admin(削除)。権限の判定は、対象の存在確認より前。トークンは 12 文字以上、役割をまたいだ重複は不可、比較は一定時間。不正な設定は、起動時に止める。
- CORS の既定は、ローカルの画面のオリジンだけ。`*` は、明示したときだけ。Cookie は使わない。
- 投入にレート制限(IP ごと、読み取り 300 / 書き込み 60 回 / 分)と、本文の上限(16 KB、411 / 413)。未知のフィールドは 422。
- Compose の既定: Redis は、パスワードつきで、ホストに公開しない(開発用の上書きファイルだけが `127.0.0.1` に公開する)。公開するポートは、すべて `127.0.0.1`。バックエンドは非 root・ハッシュ検証つきの依存。画面は、ビルドして、非 root の nginx で配信し、CSP を付ける。
- 画面のコンテナは、起動時に環境変数から `/config.js` を書く(同じイメージを、環境ごとに作り直さない)。

## Consequences
良い: 未認証の投入が拒否され、`docker compose up` の既定で Redis が外に出ない。CI のスモークテストが、公開ポート・パスワード・CSP・非 root を確かめる。
悪い: 画面から API を呼ぶトークンは、配信される JS(`/config.js`)から読める。viewer のトークンに限るか、信頼できるネットワークで使う。
      レート制限は、プロセス内のメモリで数えるため、複数台では合算されない。

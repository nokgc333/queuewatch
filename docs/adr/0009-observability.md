# ADR-0009: 観測性は、JSON ログ・Prometheus・OpenTelemetry で揃える

## Status
Accepted (2026-10-28)

## Context
ワーカーが別プロセスのため、API のログだけでは、ジョブの流れが追えない。滞留や失敗の増加に、早く気づきたい。

## Decision
- ログは JSON の 1 行 1 件(標準出力)。リクエスト ID(`X-Request-ID`。不正な値は置き換える)を、ログに自動で添える。アクセスログには、ヘッダとクエリ文字列を書かない。`/healthz` は書かない。
- `/metrics`(Prometheus)。ジョブの件数・優先度別・リトライの合計は、**スクレイプのたびに DB から数える**(ワーカーは別プロセスで、プロセス内のカウンターでは見えないため)。HTTP の件数・所要時間は、ルートのテンプレート(`/jobs/{job_id}`)ごと。未知のパスは `unmatched` に集約し、ラベルの数を増やさせない。`token` モードでは viewer のトークンが要る。
- トレースは、`OTEL_EXPORTER_OTLP_ENDPOINT` を設定したときだけ有効(API は FastAPI、ワーカーは Celery の計装)。
- Prometheus の設定と Grafana のダッシュボードの例を、`ops/` に置く。

## Consequences
良い: 滞留・失敗の増加を、ダッシュボードとアラートで見られる。ログからリクエストを追える。
悪い: メトリクスの件数は、DB への集計が、スクレイプごとに走る(数万件までは軽い)。ワーカーの処理時間のヒストグラムは、まだ無い。

# ADR-0010: ジョブの操作(キャンセル・一時停止・再開・再投入)

## Status
Accepted (2026-10-28)

## Context
デッドレターを手で再投入できず(「同名で再度 POST してください」)、待機中のジョブを止める方法もなかった。

## Decision
- 操作は 4 つ。`cancel`(待機・リトライ・一時停止 → キャンセル)、`pause`(待機・リトライ → 一時停止)、`resume`(一時停止 → 待機)、`requeue`(デッド・キャンセル → 待機、リトライ回数・エラー・進捗を 0 に戻す)。遷移は純粋関数(`domain/job_actions.py`)。それ以外は 409。
- **実行中のジョブは、操作できない**。Celery のタスクを安全に止める手段が無く、途中で殺すと、冪等性とリトライの前提が崩れるため。
- キューに残ったメッセージは取り消さず、ワーカーが、状態を見て読み飛ばす(`cancelled` / `paused` はスキップ)。取り消し(`revoke`)に頼ると、届かなかったときに、二重に動くため。
- 画面は、状態に応じて、できる操作だけを出し、結果と失敗を、読み上げ領域で伝える。

## Consequences
良い: 滞留したキューを、画面から整理できる。冪等性の前提を崩さない。
悪い: 実行中の長いレンダーは、終わるまで止められない(制限時間で止まる)。
